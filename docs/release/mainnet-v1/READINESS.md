## Что интегрировано

PR #1 → #2 → первоначальный #3 → #4, затем завершённые доработки #3 до `e66161f` / code `7e2001d`. Точные исходные SHA и порядок — в [README](README.md). Конфликты разрешены с сохранением публичных/приватных лобби, приватных приглашений, оптимизации движка, групповых долговечных команд, сетевых ограничений и восстановления платежей.

- Старый Testnet v1 сохраняет свой WASM, mock FT, конфигурацию, БД и режим кошелька. Новый v2 — отдельный адаптер и будущий отдельный deployment, не обновление v1 поверх существующего состояния.
- Для Mainnet закреплён только нативный Circle USDC `17208628f84f5d6ad33f0da3bbbeb27ffcb398eac501a31bd6ad2011e36133a1`; USDC.e, mock FT и совпадение одного символа USDC не принимаются. Требуются API v2, точный code hash, 6 decimals, явный получатель комиссии и ставка комиссии 300 bps общего банка.
- Депозит, revision/terms, семь серверных методов, старт, результат, фиксированные получатели, отмены, refunds и claim согласованы с Rust API. Успех отправки или верхнего receipt не подменяет подтверждённый приём депозита либо Paid.
- Сетевые БД, deployment identity, сессии и браузерные журналы разделены. Mainnet private signer не загружается. `runtimeKeyChecked` означает только проверку публичных прав; `signerChecked=false` не создаёт ложного утверждения о владении private key.
- Обучение, одиночная экономика, бот и автономная сборка сохранены. Старые прототипы не заменялись.

## Замечания, исправленные при интеграции

- R01/A04: каталог не создаёт новые параллельные поколения при изменении списка, ошибки сохраняют negative TTL, сессии одного аккаунта делят бюджет.
- P4-01: восстановленный матч не получает накопленное до reconnect время; backlog остальных матчей сохраняется.
- R05/R07 и policy: точные receipt/transaction binding, original-hash recovery, новые freeze/deadline refunds, 3% и явный fee receiver, immutable replay с привязкой к on-chain match ID.
- R08: история больше не стоит перед heartbeat; свежие live checks ограничены, история обслуживается порциями round-robin. Приоритет heartbeat не обходит уже подписанные nonce: неизвестный предшественник блокирует новую подпись, исходные bytes сохраняются.
- K1: каталог внутри проекта с именем, начинающимся на `..`, не считается внешним местом signer. Проверка отклоняет пустой тестовый credential до чтения ключа.

Первичные и повторные отчёты другого агента сохранены в `security-baseline/`. Их выводы привязаны к конкретным SHA; passing EXPOSURE-тесты старых ошибок не считаются свидетельством их исправления. Это технический AI-review, не независимый профессиональный аудит.

## Что блокирует денежный запуск

Подробный реестр — [BLOCKERS](BLOCKERS.md). Существенные оставшиеся границы:

1. C1: успешный FT transfer с потерянным callback может оставить InFlight; proof-based repair API отсутствует. Автоматического reset и двойной выплаты нет.
2. C2/C3/A06: failed resolver может оставить unaccounted FT без безопасной атрибуции; потерянный hash, архивные receipts и окончательно неизвестные подписанные операции требуют отдельной incident/recovery процедуры. Неизвестная подпись консервативно блокирует новые.
3. A01/A08: доверенный сервер определяет победителя. Нужны утверждённые лимиты экспозиции, dispute-модель, governance и инвентаризация deployment/admin/runtime прав.
4. A03/A05: истёкшие лобби с одним депозитом всё ещё занимают capacity; keeper/Sybil admission, долговечная история, квоты и disk-pressure защита не завершены. Оплаченные обязательства не удаляются ради тестов.
5. Реальная ingress/proxy защита, резервное восстановление на VPS, SLA, массовые кошельки и on-chain пропускная способность не подтверждены.
6. Требуются профессиональный независимый аудит и retest, юридическое заключение по странам/возрасту/AML-KYC/ToS и реализованный допуск пользователей. Их не заменяет этот отчёт.

Исторический v1 WASM не совпал с пересборкой сохранённого v1 source; причина не установлена. V2 проверен как отдельный воспроизводимый кандидат. Параметры cap 5%, delay 48h и deadline 6h остаются предложенными audit-политиками PR #1, а не новым разрешением применять другой тариф вместо 3%.
